摘要 / Abstract

问题Sec. VI 把 N 皇后合法构型数写成一个由 17-entry 局域张量组成的 PEPS 收缩。理论表示很紧凑，但它能否形成具有竞争力的精确算法，取决于中间张量如何表示和收缩。

方法我们从显式 rank-9 张量 B 和 rank-8 张量 C 出发，在 60 个独立 worktree 中依次检验局域编译、稀疏边界、对称性、决策图、低秩、路径搜索、精确算术与 CPU 热核；每条快路径都必须回放到 explicit C。

结果最重要的转折不是某个微架构技巧，而是 E38 的 contraction reassociation：前缀继续合并相同边界，后缀不再物化宽 frontier，而改为流式递归收缩。N=15 的同批链由 0.767 s、641.8 MB 降至 0.0712 s、10.7 MB。

结论对这个非负、极稀疏、强约束网络，精确收缩经过 partial evaluation 与 reassociation 后自然趋近位掩码状态搜索。它没有改变指数增长，也没有得到 Q(28)，但给出了“何时张量收缩会编译成搜索”的可验证案例。

本文的贡献不是“PEPS 打败 DFS”，而是揭示：当局域张量主要编码确定性约束传播时， 决定精确收缩成本的不是裸拓扑宽度，而是每个 cut 上真正存活的 sparse support，以及仍需展开的 continuation 数。
方法研究成功建立了从 explicit B/C 到 competitive search-like contraction 的完整保真链，并解释了关键成功与失败机制。
挑战尚未完成最大完整结果为 Q(22)；当前单节点 Q(28) 外推约 105–214 年，不能把 no-go 分析写成 Q(28) 已完成。
01

The question

17 个局域非零元，为什么仍然会变成一个困难的全局计算？

N 皇后要求每行、每列恰有一个皇后，两族对角线至多一个。Liu–Liao–Wang 的 Sec. VI 把这些规则写进四条二值约束通道：行、列、右下对角线与左下对角线。

局域张量很小

每个格点有物理占据指标 α∈{0,1}，以及四个通道各一入一出的八条二值虚腿。 当 α=0 时，四个通道独立地原样传递 0 或 1，共 24=16 项； 当 α=1 时，四个 incoming 都为 0、四个 outgoing 都为 1，只有 1 项。

因此 rank-9 的 B 恰有 17 项；对 α 求和得到 rank-8 的 C=ΣαB，仍恰有 17 项。

全局收缩很大

v0=(1,0) 初始化每条约束线；行列终点使用 v1=(0,1)，强制恰好一个； 对角线终点使用 v2=(1,1)，允许零个或一个。局域规则虽只有 17 项， 但开放边界必须同时记住所有尚可能延拓的列与对角线历史。

02

The wrong question

我们以为要找一条更好的路径，后来发现先问错了成本函数

最初的朴素算法逐格点应用 C，把一整行之后相同的开放边界合并。这是忠实的 sparse PEPS contraction， 也是一个危险的诱惑：只要继续优化哈希、排序、对称性和 contraction order，似乎就能解决扩展性。

1,197.1 s冻结朴素 PEPS 在同一 SCNet 节点计算 N=16
30.625 GiB同一进程的 GNU time 最大 RSS
194.21 M峰值 sparse support；不是 bond dimension 本身

E1–E37 的许多优化都真实有效：按 incoming signature 索引 C、压缩 key、buffer reuse、 sort-reduce、vertical reflection、sharding、紧凑 entry 与窄算术，持续降低了每条记录的成本。 但它们大多没有改变一个事实：晚层仍要生成、写入、排序和聚合巨量记录。

第一个认识：把错误的中间表示做得非常高效，仍然不会得到可扩展算法。 对 flat frontier，时间和内存由“真实物化多少条记录”主导，而不是由局域 C 只有 17 项这一事实主导。

当时的直觉实际观察修正后的问题
最小 dense width 的路径应更好generic site-tree 可产生更大的实际稀疏中间张量路径评分必须看 actual support 与 materialized bytes
D4 群有 8 个元素，应接近 8×interior row cut 的便宜 stabilizer 基本只有左右反射只计算 cut 上可比较且低开销的对称作用
检测到低秩即可压缩构造矩阵与消元先发生 fill-in，收益出现得太晚压缩必须进入 apply，而非事后处理巨型对象
热点占 99.98%，微调热点就能大幅提速热点本身是必要的指数 C-state expansion必须减少 transitions，而非只移动相同工作
03

The turning point

E38：不再优化那座巨型中间张量，而是不再建造它

研究的结构转折发生在 E38。网络、局域张量、边界条件和精确算术都没有改变； 改变的是 contraction association：早期行仍合并相同边界，晚期行改为逐 prefix 流式递归收缩。

同一个 Sec. VI 网络，两种中间表示

BEFORE · E32 / N=15

整层物化

生成所有 row candidates → 写入 records → 全局 sort → reduce → 下一层。

0.7674 s · 641.8 MB

→
AFTER · E40 / N=15

合并前缀 + 递归尾部

只物化前四行的 7,426 个 sectors；每个 sector 独立消费剩余 C tensors。

0.0712 s · 10.7 MB

10.8×同批时间改善
59.9×RSS 缩减
7,426峰值 prefix support

E38 首先证明这个方向成立：N=15 由 E37 的约 0.466 s、333.5 MB 降至 0.1408 s、30.9 MB。 E40 再用 actual-support probe 选择 cut，并由 explicit C 认证位计划。E42/E47 随后把最后四至六行 编译成 terminal supernode，继续删除通用递归与重复 mask setup。

故事的高潮不是速度，而是工作量开始重合。
PEPS E47：91,883,705 accepted C entries DFS：91,883,698 placements

在 N=15 上，两条独立实现只相差 7 个计数事件。它们没有互相调用，也没有读取已知 Q(N)； 它们只是从不同起点抵达了几乎相同的状态展开。这是“精确收缩自然变成搜索”的直接工程证据。

04

The mechanism

为什么它像 DFS，却仍然是保真的 PEPS 收缩？

等价命题 · 实现中逐状态验证

Sec. VI 行转移与三 mask 约束自动机同构

在 v0 初始化、行终点 v1 和对角终点 v2 下， 消去一行内部虚腿后，C 的 16 个 pass-through 项与唯一 occupied 项决定：

A = ¬(columns ∨ diag↘ ∨ diag↙) ∧ board_mask

A 的每个置位都对应 C 中唯一允许的占据转移；选中 q 后，列信号保留、两族对角信号随行推进移位。 因此 low-bit extraction 不是外加的 N 皇后先验，而是对 C-derived sparse relation 的枚举次序。

  1. 显式来源：B 与 C 在运行时构造并验证各 17 项；编译器只遍历 C.entries()。
  2. Fail closed：若 16 个空传播项、唯一 occupied 0→1 项、系数或边界不符合 Sec. VI，快路径拒绝生成。
  3. 逐 parent 回放：每个可达 parent 的 compiled successors 与 sitewise explicit-C multiset 对齐；terminal 显式施加 column v1 与 diagonal v2。
  4. 独立对照：dfs_bitmask.rs 是独立模块，只作 oracle/comparator；PEPS solver 不调用它，也不读取 known-count table 产生答案。

正确分类：最终方法是 proved-equivalent optimized PEPS contraction， 不是 naive sitewise scan，也不应冒充 conventional DFS。二者热循环相似，是等价命题的结果，恰恰是本文要解释的现象。

05

The evidence

优化改变了资源形态，却没有改变指数尾部

同节点对照显示了两件同时成立的事实：第一，保真编译可以把朴素 PEPS 的巨大时间与内存成本消掉四个数量级； 第二，最新 PEPS 与位掩码 DFS 的增长曲线最终汇合，而不是出现新的渐近斜率。

17,337×N=16：最新 PEPS 相对冻结朴素显式-C 路径的时间差
3,113×N=16：30.625 GiB → 10.074 MiB 的 RSS 差
≈同一曲线N=14–21：latest PEPS 与 DFS 的增长与吞吐进入同量级

最大完整结果：Q(22)

production E50 在 SCNet 独占 128-core AMD EPYC 7742 节点上得到 Q(22)=2,691,008,701,644。count-only 用时 10,112.287 s（2.81 h）； 随后的 checked-u128 指标回放用时 19,948.064 s，因此整个 GNU time -v 进程墙钟为 8:21:00，最大 RSS 为 57,892 KiB。

内存问题基本被解决。prefix support 只有 612,106；N=22 不再需要巨型晚层 frontier。

时间问题没有被解决。指标回放记录 143,257,397,145,757 个 recursive nodes；瓶颈变成低复用 exact C transitions。

06

The wall

为什么低内存并不意味着 Q(28) 已经接近

当 frontier 物化被消除后，RSS 不再随中间状态数爆炸；但每个合法 prefix 仍必须展开其 exact continuation。 算法从 memory-bound 的边界合并器，变成 compute-bound 的指数遍历器。

Go / no-go 结论：NO-GO。当前 kernel 不应直接提交完整单节点 Q(28)。 要跨越六个 N，必须减少 exact nodes/support 或更换吞吐平台；继续追求 1%–4% 的 scalar hot-loop 改善不可能改变资源结论。

这不是“PEPS 永远不能得到 Q(28)”的数学证明，也不是排除 separator、meet-in-the-middle、 新的 symmetry-canonical representation 或 finite-field GPU traversal。它只是对当前 revision 的可复现实测边界负责。

07

Negative results

失败不是附录噪声：它们共同指出“标准 proxy 为什么失真”

60 个方向的价值不在于数量，而在于多个互相独立的失败都指向同一机制： 对 value-sparse constraint tensors，拓扑、群阶、秩和 SIMD lane 数都可能是错误的成本代理。

Generic TreeSA
优化 proxy：dense width / topology
N=8–11 的 exact executor 全部通过计数，但 peak support 相对逐行路径膨胀 8.38×–109.05×；N=20 仅生成 width-60 plan，没有冒险提交 exact executor。
DD / future quotient
优化 proxy：逻辑共享应自动压缩状态
共享确实存在，但 canonicalization、hash 和 concrete-support materialization 先支付成本；压缩发现结构的时机太晚。
Exact rank / PLUQ
优化 proxy：低秩意味着低成本
边界可表现出低秩，但矩阵构造和消元产生 fill-in；“结果低秩”不等于“能廉价地产生低秩结果”。
完整 D4
优化 proxy：8 个群作用带来接近 8×
除 vertical reflection 外，多数作用在 row cut 上很晚才可比较；额外 nodes 只降 1.3%–1.8%，N=15 反而慢约 3.2%。
SIMD / cache / ILP
优化 proxy：99.98% 热点意味着大量局部余量
suffix cache 命中率低于 0.28%，显式 AVX2 与 scalar lockstep 回退；热点主要是不可省的、数据依赖强的 C-state expansion。
由负面结果导出的设计原则

下一代路径搜索不应只输出 contraction tree；它必须联合选择路径、局域编译、在线压缩和目标 observable，并以 actual support、物化字节与实测 kernel cost 评分。

Approximation diagnostic

有限 χ 看起来扩展良好，只因为它丢掉了几乎全部计数

我们另外实现了常规 Float64 boundary-MPS 截断。row MPO 仍由 explicit C 生成， 但 QR/SVD 后把边界维数截到 χ。这是独立的近似诊断，不属于 exact Issue #34 solver。

13.4036χ=128 得到的 N=14 浮点计数估计
99.9963%相对误差；只保留精确计数的 3.67×10⁻⁵
≈13,100× 慢χ=128 截断相对同节点 exact PEPS 的时间比

这不是对所有物理 PEPS 截断的否定。它说明更窄的一件事：当 observable 是构型简并度、 残余熵或受约束 Hilbert 空间维数时，局部 Schmidt/Frobenius discarded weight 不会自动给出最终计数的相对误差界。误差必须针对目标配分函数或 observable 单独验证。

09

Why it matters

这项工作的价值，不在于刷新 N 皇后纪录

N 皇后只是一个可审计的压力测试：局域规则极稀疏、答案可独立验证、失败边界足够陡。 真正可迁移的是一套处理强约束张量网络的方法论。

1Support-aware
路径代价必须包含实际存活 sector，而非只看 cut 上有多少 legs。
2Compile local rules
ice rule、Gauss law、blockade 等应编译成 sparse automaton，而非反复解释为 dense einsum。
3Hybrid environments
边界小时合并 sector，边界将爆炸时切片并流式消费尾部。

自旋冰与受挫体系

two-in/two-out ice rule 可写成局域稀疏张量；全收缩对应合法冰构型数和残余熵。 本研究提示：若约束使大量 sector 精确为零，actual-support-aware contraction 可能比只优化 dense topology 更合适。

Rydberg blockade 与独立集

阻塞图上的合法激发构型等价于独立集；其计数给出受限 Hilbert 空间维数， 加 fugacity 后得到 hard-core 配分函数。局域规则编译与 merge/tail 切换可以直接形成可检验的算法假设。

适合写进论文标题的主张

精确稀疏张量网络可通过局域 partial evaluation 与 contraction reassociation，保真地编译成竞争性的搜索型执行器；N 皇后提供了这一转化的机制证据、失败图谱与资源边界。

本文已经建立

  • Sec. VI B/C 与 v0/v1/v2 的显式实现和测试；
  • 张量 → 行自动机 → merge/tail contraction 的保真链；
  • 从朴素 frontier 到 Q(22) production 的实证演化；
  • TreeSA、DD、低秩、D4、SIMD 与截断的机制化负面结果。

本文没有声称

  • PEPS 拥有比 bitboard DFS 更低的渐近指数；
  • 当前 comparator 代表所有同等优化的 DFS；
  • 已经复现 Q(27) 或计算 Q(28)；
  • N 皇后的结论无条件适用于一般复数、稠密、纠缠 PEPS。
