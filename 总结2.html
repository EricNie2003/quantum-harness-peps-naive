四个演化阶段

每个阶段的“主瓶颈”不同，所以同一个优化在不同阶段可能从 KEEP 变成无效。

阶段 A · 解释与容器

E1–E10：消除 17-entry 扫描、压缩 key、复用 buffer、改用 sort-reduce、并行 slicing。结果是串行约 8.17×，但 support 完全没降。

阶段 B · 结构压缩探索

E11–E35：D4 vertical 成功；DD/ZDD、low-rank、future quotient 证明结构存在，但大多因先物化 concrete support 而无法生产化。

阶段 C · record traffic 与 association

E24–E47：shards、紧凑 entries、bounded flush、窄算术；E38/E40 把晚层改为 recursive tail；E42/E47 编译 terminal supernode。

阶段 D · 热核边际耗尽

E48–E60：stack、SIMD、cache、I-cache、ILP、更多 unroll 全部未过 gate。99.98% 热点是必要的低复用 C-state expansion，不是可删 wrapper。

每个被接受的优化：做了什么、为何成功

这里列出 19 个 production KEEP 与 E45 可选 exact/低内存 backend。研究证据类 KEEP 另在分类与矩阵中标记。

E1C 输入签名索引
生产 KEEP局域算子与稀疏转移
关键结果N=14 25.1915→19.3084 s；局域扫描减少 93.8%

做了什么

在 SiteTensorC::from_b 生成 17 个非零元后，再按四个 incoming virtual bits 机械分桶。收缩时不再扫描 17 项，而是只读取对应 signature 的小桶。

为什么有效

这是对显式 C 的索引化，不改变局域 truth table。收益直接来自消除大量不可能匹配的局域项检查。

没有解决什么

peak boundary support、HashMap 状态数和物化方式完全不变，因此只能解决局域扫描常数。

E6由显式 C 编译 exact row operator
生产 KEEP局域算子与稀疏转移
关键结果N=14 11.0897→5.8532 s，约 1.89×

E9exact sort-reduce 替代 HashMap 物化
生产 KEEP物化、排序与聚合
关键结果N=14 6.0380→3.0850 s；RSS 666.17→444.28 MiB

做了什么

层输出先顺序写入连续 vector，再按完整 packed key 排序，最后原地 checked-u128 reduce；不再边生成边插入 HashMap。

为什么有效

即使重复 key 不多，顺序写入、紧凑 entry、cache-friendly sort 和避免随机 probing 仍带来近 2×收益。该实验推翻了“merge ratio 低所以 sort-reduce 不值”的旧模型。

没有解决什么

仍然物化完整 candidate 层；排序和内存流量后来成为新瓶颈。

E38C-derived recursive tail hybrid
生产 KEEP收缩路径、宏与分隔面
关键结果N=15 0.4656→0.1408 s；RSS 333.5→30.9 MB

做了什么

选择一个 cut：前几行仍用 exact sparse sort-reduce 形成 prefix sectors；剩余行不再逐层物化，而是递归消费 compiled-C successor。

哪些思路成功，哪些失败，为什么

以下结论是跨多轮消融重复出现的机制，而不是单个 benchmark 的偶然胜负。

成功模式

机械 partial evaluation

E1、E6、E11/E24、E40 都从显式 C 自动推导快路径。成功前提是 fail-closed 编译与逐 parent replay，而不是手写替代模型。

减少真实 record bytes/traffic

E3、E9、E24、E26、E28、E31、E32、E36、E37 持续有效。只要算法仍物化 frontier，bytes/entry、顺序访问和 capacity 就直接映射为 wall/RSS。

只用 cut 上便宜可比较的对称性

E12 的 vertical reflection 约 2×且稳定；它减少真实 state/candidate，而不是对最终答案形式上除以群阶。

改变 contraction association 以避免物化

E38/E40 是最大转折：不再对晚层写入并排序整层 records。它比继续优化 sort/hash 更接近根因。

由 exact certificate 选择窄算术和 terminal supernode

E32/E36/E45/E46/E42/E47 把 exactness 证明转化为更窄数据路径和更少控制开销。

并行必须与内存组织共同设计

E10 有初期收益但很快饱和；E31 只有在按 parent counts 均衡并 bounded flush 后才同时改善 wall 和内存。

失败模式

只调容器参数，不改变访问模式

E2、E4a 失败；E51–E53 在后期也说明 task/RSS/balance 不是 99.98% 热核主体。

post-hoc 压缩太晚

E14/E15 证明 quotient/low-rank 真实存在，但 E16–E18、E35 都必须先访问 concrete graph；在物化后压缩无法成为生产收益。

generic DD/BDD 的共享假设不成立

E7、E21–E23 的 nodes/support 大于 1 或仅小幅下降；hash-cons/apply 成本超过共享。

按几何或 dense proxy 搜路径

E8、E13、E19、E20、E29、E30、E34 失败，因为实际活跃 constraint lines、canonical merge 和 tensor-value macro 比抽象 width 更重要。

期待 memoization，但状态几乎不汇合

E44、E54、E60 的 hit/duplicate 比例太低；查询成本施加在每个 node 上。

手写 radix/SIMD/stack/ILP 未胜过编译器与现有库

E33、E48–E50、E55–E59 的额外 pass、spill、divergence、代码增长或控制开销超过收益。

full D4 不等于 8×

E39 额外只降 1.3–1.8% nodes 且变慢；多数群作用在当前 cut 上不能提前比较。

减少候选峰值不等于减少 RSS/时间

E27 的 retained runs 与最终输出重叠，heap operations 爆炸；E41 删除很小的 prefix merge 也触碰不到指数 tail。

  • 尚未证明：PEPS 的渐近 exponent 更低，或能超过所有优化过的 N-Queens DFS。
  • 最大完整 exact count：Q(19)，由 E45 wide CRT 后端完成。
  • Q(28)：按当前 recursive-tail 增长仍粗略需要 800–1000 年；key width/CRT 已不是主限制，指数 C-transition 数才是。
  • 后期热点：`contract_certified_tail_last_k_u64::<6>` 占 99.979% leaf samples；E56–E60 表明同类 CPU-local 微调通常只剩 1–4%。
